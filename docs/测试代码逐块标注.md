# 测试代码逐块标注（conftest.py / test_auth.py / test_order.py）

## 标注图例

| 标记 | 含义 | 你该怎么做 |
|---|---|---|
| 🟩 **固定骨架** | 框架或库的规定写法，全世界都一样 | **照抄，不用理解内部原理**。只有注释里写到的 1~2 处需要换成自己项目的东西 |
| 🟨 **改参数** | 结构不变，换 URL / 请求体 / 期望值就能复用 | **复制粘贴改三处**，10 秒一条新测试 |
| 🟦 **必须理解** | 不懂就会写出"永远不红"的假测试 | 需要真正看懂，因为在你的代码里会反复用到 |
| 🟥 **自己设计** | 没有标准答案，取决于业务规则 | 只能自己想：该测什么、边界在哪、断言哪一条 |

一句话分工：**🟩🟨 是体力活（占 70%），🟦🟥 是脑力活（占 30%，但决定测试有没有价值）。**

# 一、`tests/conftest.py`（67 行）

这个文件是**纯基础设施**：没有任何一条测试，只有可复用的零件。它 90% 是 🟩，你几乎不用改。

## 1-5 行 · 文件说明

```
'''pytest 公共夹具（fixture）

约定：每个测试函数都跑在一个全新的 SQLite 内存库里，测试结束即销毁。
好处：测试之间互不污染，也不会动到 MySQL 里的真实数据。
'''
```

🟩 **固定骨架**。三引号字符串就是注释，pytest 不读它，写给人看。换项目时改文字即可。

## 6-10 行 · import 区

```python
import httpx
import pytest_asyncio
from tortoise import Tortoise

from main import app
```

🟩 **固定骨架**，只有最后一行的 `from main import app` 是**你项目的**入口。

| 行 | 必须装 | 说明 |
|---|---|---|
| `httpx` | `pip install httpx` | 用它当 HTTP 客户端，不用 requests（requests 不支持 async） |
| `pytest_asyncio` | `pip install pytest-asyncio` | 让 pytest 支持 async 测试和 async fixture |
| `Tortoise` | 已有 | 手动初始化测试库 |
| `from main import app` | — | **唯一的自项目依赖**。换项目只改这行（换成你的 FastAPI 实例） |

> 这行能成功，全靠 `pytest.ini` 里的 `pythonpath = .`。否则报 `ModuleNotFoundError: No module named 'main'`。

## 12-21 行 · 测试库配置

```python
TEST_DB_CONFIG = {
    "connections": {"default": "sqlite://:memory:"},
    "apps": {
        "models": {
            "models": ["app.infrastructure.database.orm_models"],
            "default_connection": "default",
        }
    },
}
```

🟨 **改参数**：结构固定（Tortoise 规定死），只有两处要换成自己项目的值。

| 要改的 | 换成什么 |
|---|---|
| `"sqlite://:memory:"` | **不要改**。这是测试库的核心——内存库，跑完即消失，绝不碰 MySQL |
| `"app.infrastructure.database.orm_models"` | **要改**成你项目里模型所在的**模块路径字符串**（点号分隔，不带 `.py`） |

三个键的含义：

- `connections`：`别名 → 连接串`。`default` 是别名，代码里没写别名时用它
- `apps`：逻辑分组，可以有多个（比如业务库 + 报表库）。这里只要一个
- `apps.models.models`：模型文件路径**列表**。注意是字符串不是模块对象——Tortoise 靠它延迟 import，避免循环依赖

> 判断标准：如果测试跑起来报 `Table 'orders' doesn't exist` 或 `No tables found`，八成是这里的路径写错了。

## 24-30 行 · 数据库初始化夹具

```python
@pytest_asyncio.fixture(autouse=True)
async def init_db():
    '''autouse=True：每个测试自动执行，不用手动声明'''
    await Tortoise.init(config=TEST_DB_CONFIG)
    await Tortoise.generate_schemas()      # 按模型建表（测试里不走 aerich）
    yield
    await Tortoise.close_connections()
```

🟩 **固定骨架**（🟦 但必须理解 `yield` 和 `autouse` 这两点，否则调试时会困惑）。

| 元素 | 类型 | 说明 |
|---|---|---|
| `@pytest_asyncio.fixture` | 🟩 | async fixture 必须用它。换成普通的 `@pytest.fixture` 会把协程对象当返回值，测试里一 await 就炸 |
| `autouse=True` | 🟦 | 自动应用到**每个**测试，测试函数参数里不用写 `init_db`。所以你看 15 条测试里一次都没出现过它 |
| `Tortoise.init(config=...)` | 🟩 | 建立连接。Tortoise 是全局单例，每个测试重新 init 会覆盖上一次 |
| `generate_schemas()` | 🟩 | 按模型定义建表。测试里**不走 aerich**——迁移脚本是给生产库升版本用的，测试库每次都是空的，直接建表最省事。顺带也验证了模型定义本身合法 |
| `yield` | 🟦 | 分界线：上面是 setup，下面是 teardown。**不带值**的 yield = 这个 fixture 不提供任何数据，只负责"前后各做一件事" |
| `close_connections()` | 🟩 | 销毁连接。不写会残留连接池，测试多了会报连接数超限 |

**为什么不能靠 `main.py` 的 lifespan 自动初始化**：`httpx.ASGITransport` **不执行 lifespan**（只有 Starlette 的 `TestClient` 才会）。指望应用启动时连库，测试里 Tortoise 就是未初始化，第一个请求直接 `ConfigurationError`。

## 33-38 行 · HTTP 客户端夹具

```python
@pytest_asyncio.fixture
async def client():
    '''不打网络、不起 uvicorn，请求直接送进 ASGI 应用'''
    transport = httpx.ASGITransport(app=app)
    async with httpx.AsyncClient(transport=transport, base_url="http://test") as c:
        yield c
```

🟩 **固定骨架**，逐字照抄。

| 元素 | 说明 |
|---|---|
| `ASGITransport(app=app)` | 把 FastAPI 应用包成 httpx 的"传输层"。请求**不经过 TCP**，直接调用 ASGI 接口——不用先启动 uvicorn，也不占 8000 端口 |
| `base_url="http://test"` | 🟦 **必填**。httpx 要求 URL 是绝对的，测试里只写 `/api/v1/orders/`，前缀由它补。主机名 `test` 随便起，不会真发 DNS |
| `async with ... as c` | 上下文管理器负责关闭连接池 |
| `yield c` | 这里**带值**：把客户端交给测试函数，测试函数的 `client` 参数拿到的就是它 |

> 对比上一个 fixture 的裸 `yield`：**带值 = 提供数据；不带值 = 只做前后处理**。这是 fixture 唯一的两种形态。

## 41-52 行 · 登录辅助函数（普通函数，不是夹具）

```python
async def _login_headers(client, username: str, password: str = "pass1234") -> dict:
    '''注册 + 登录，返回可直接用于请求的认证头'''
    await client.post(
        "/api/v1/auth/register",
        json={"username": username, "password": password},
    )
    resp = await client.post(
        "/api/v1/auth/login",
        json={"username": username, "password": password},
    )
    assert resp.status_code == 200, resp.text
    return {"Authorization": f"Bearer {resp.json()['access_token']}"}
```

🟨 **改参数**：结构固定，只有 URL 和字段名可能不同。

| 参数 | 类型 | 说明 |
|---|---|---|
| `client` | `httpx.AsyncClient` | **必须显式传**，因为这不是 fixture，拿不到自动注入 |
| `username` | `str` | 必填。用户名唯一，一个测试要多个用户时靠它区分 |
| `password` | `str`，默认 `"pass1234"` | 有默认值，绝大多数用例不用传 |

换项目要改的三处：

| 位置 | 改什么 |
|---|---|
| 两个 URL 字符串 | 你的注册 / 登录路径 |
| `json={...}` 的键名 | 你接口的字段名（`username`/`password` 是常见命名，不是通用） |
| `"Bearer "` 前缀 | 若你的 security 用 `HTTPBearer` 就不用改；用 `APIKeyHeader` 之类要换成对应格式 |

🟦 **必须理解的两个点**：

**① 名字以下划线 `_` 开头**：pytest 只收集 `test_` 开头的函数，所以 `_login_headers` 不会被误当成测试。命名是有意的保护。

**② 忽略 register 的返回码**：所以同一个用户名重复调用不会报错——第二次 register 返回 400（重复），login 依然成功。这让 `login_headers("alice")` 可以在多个测试里安全重复调用。

## 55-58 行 · `auth_headers`（直接给值）

```python
@pytest_asyncio.fixture
async def auth_headers(client):
    '''默认用户 alice 的认证头'''
    return await _login_headers(client, "alice")
```

🟨 **改参数**：`"alice"` 是默认用户名，改成什么都行。

🟦 用法：测试函数写 `headers=auth_headers` 直接用，**不要加括号、不要 await**。

## 61-67 行 · `login_headers`（工厂）

```python
@pytest_asyncio.fixture
async def login_headers(client):
    '''工厂夹具：想用哪个用户就调哪个'''
    async def _make(username: str, password: str = "pass1234") -> dict:
        return await _login_headers(client, username, password)

    return _make
```

🟩 结构固定（"夹具套函数"是标准写法），🟦 必须理解它和上一个的区别：

| 夹具 | 返回什么 | 怎么用 | 场景 |
|---|---|---|---|
| `auth_headers` | dict | `headers=auth_headers` | 只需要一个用户 |
| `login_headers` | **一个协程函数** | `headers = await login_headers("bob")` | 一个测试里要多个用户 |

多包这一层的唯一目的：把 `client` 藏起来。测试函数只关心用户名，不用管客户端从哪来。

**为什么不能把 token 塞进 `client.headers`**：塞进去之后整个测试只有一种身份，`test_list_returns_own_orders_only` 这种"同时扮演 alice 和 bob"的越权测试就写不出来了。这是整套夹具最重要的设计决定。

# 二、`tests/test_auth.py`（73 行）

## 1-5 行 · 文件说明 + 路径常量

```python
'''认证接口测试：注册 / 登录 / 受保护接口'''

REGISTER = "/api/v1/auth/register"
LOGIN = "/api/v1/auth/login"
ME = "/api/v1/auth/me"
```

🟨 **改参数**。三个常量是本文件唯一的"项目相关配置"。换项目只改这三行，下面 8 条测试全都不用动。

好处：路径写错时的报错信息会显示常量名，而不是散落在 8 个地方的字符串。

## 每条测试的统一骨架

8 条测试长得都一样，先看骨架再看差异：

```python
async def test_xxx(client):                        # 🟩 函数壳 + 🟨 函数名
    resp = await client.post(URL, json={...})      # 🟨 URL / 方法 / 载荷
    assert resp.status_code == 201                 # 🟨 期望的状态码
    body = resp.json()                             # 🟩 固定
    assert body["字段"] == 值                       # 🟥 断言什么，由你决定
```

四行的性质完全不同：

| 行 | 标记 | 为什么 |
|---|---|---|
| `async def test_xxx(client):` | 🟩 壳 + 🟨 名 | 壳固定（`async def` + `test_` 前缀）；**名字要能说清测什么** |
| `await client.post(...)` | 🟨 | 换 URL、`json=`、`params=`、`headers=` |
| `assert resp.status_code == N` | 🟨 | 换数字。422 是参数校验、400 是业务拒绝、401 未认证、404 不是你的资源、409 冲突 |
| `assert body[...]` | 🟥 | **没有标准答案**，断言哪几个字段决定了这条测试的价值 |

## 逐条详解

### 1. `test_register_success`（8-15 行）

```python
async def test_register_success(client):
    resp = await client.post(REGISTER, json={"username": "tom", "password": "pass1234"})
    assert resp.status_code == 201
    body = resp.json()
    assert body["username"] == "tom"
    assert body["user_id"] > 0
    assert "password" not in body          # 响应里绝不能出现密码/密文
```

| 行 | 标记 | 说明 |
|---|---|---|
| `json={"username": "tom", ...}` | 🟨 | 用户名随便起，只要本测试内唯一 |
| `== 201` | 🟨 | 注册成功用 201（Created），不是 200 |
| `body["user_id"] > 0` | 🟥 | 断言"主键被数据库回填了"，而不是断言具体值（自增 id 不该硬编码） |
| `"password" not in body` | 🟥 | **最有价值的一行**。哪天有人图省事 `return user.__dict__`，密码哈希立刻漏出去，这条当场变红 |

注意 `not in` 判的是**顶层键名**，不是整个字符串。想更严可以加 `assert "password_hash" not in body`。

### 2. `test_register_duplicate_username`（18-25 行）

```python
async def test_register_duplicate_username(client):
    payload = {"username": "tom", "password": "pass1234"}
    await client.post(REGISTER, json=payload)
    resp = await client.post(REGISTER, json=payload)
    assert resp.status_code == 400
    assert resp.json()["detail"] == "用户名已经存在"
```

| 元素 | 标记 | 说明 |
|---|---|---|
| `payload` 变量提出来 | 🟨 | 两次请求要用完全相同的载荷，提成变量避免手抖 |
| 忽略第一次的返回码 | 🟩 | 测试只关心第二次 |
| `== 400` | 🟨 | 当前实现里 4 种业务异常都被路由压成 400。将来上全局异常处理器后这里要改成 **409** |
| `detail == "用户名已经存在"` | 🟥 | 断言**具体文案**。好处是能卡住"文案被悄悄改掉"；坏处是文案一改测试就红。团队通常只在关键提示上这么写 |

### 3. `test_login_success`（28-37 行）

```python
assert body["token_type"] == "bearer"
assert body["expires_in"] > 0
assert len(body["access_token"].split(".")) == 3      # JWT 就是三段
```

| 行 | 标记 | 说明 |
|---|---|---|
| `token_type == "bearer"` | 🟥 | OAuth2 规范值，写死是对的 |
| `expires_in > 0` | 🟥 | 用 `> 0` 而不是精确值——有效期会变，不该锁死 |
| `split(".")` 长度 3 | 🟥 | **这条比 `startswith("eyJ")` 强**：万一有人把 token 实现换成随机 UUID 存 Redis，这条立刻红，因为那样就不是 JWT 了 |

### 4-5. `test_login_wrong_password` / `test_login_user_not_exists`（40-53 行）

```python
assert resp.json()["detail"] == "用户名或密码错误"       # 不暴露"用户不存在"
```

🟥 **两条测试断言同一句文案是刻意的**。用户不存在和密码错误必须返回一样的信息，否则攻击者能靠差异枚举出哪些用户名已被注册。这叫**用户名枚举漏洞**，是渗透测试的常见检查项。

这类"两条测试故意相同"的设计，是测试里最有意思的部分——它不是验证功能，是验证**安全策略**。

### 6. `test_me_without_token`（56-60 行）

```python
resp = await client.get(ME)
assert resp.status_code == 401
assert resp.json()["detail"] == "未提供访问凭证"
```

| 元素 | 标记 | 说明 |
|---|---|---|
| `client.get(ME)` 不传 headers | 🟨 | 故意不带认证头 |
| `401` | 🟨 | 未认证 = 401；已认证但无权限才是 403。这两个别混 |

### 7. `test_me_with_token`（63-67 行）

```python
async def test_me_with_token(client, auth_headers):
    resp = await client.get(ME, headers=auth_headers)
    assert resp.status_code == 200
    assert resp.json()["message"] == "已认证"
```

🟦 **这里演示了两个参数的分工**：`client` 负责发请求，`auth_headers` 负责身份。参数顺序无所谓，pytest 按名字注入。

这条和上一条构成对照实验：**唯一变量是有没有认证头**。写测试时尽量让两条相邻的测试只差一个变量，失败时能直接定位原因。

### 8. `test_me_with_invalid_token`（70-73 行）

```python
resp = await client.get(ME, headers={"Authorization": "Bearer abc.def.ghi"})
assert resp.status_code == 401
```

🟨 **改参数**：`abc.def.ghi` 是伪造的 JWT 形状（三段但签名无效）。也可以换成空字符串、乱码、其他项目的真 token——**这些都属于"应该被拒"的输入**。

🟥 值得想一下：这条只断言 401，没断言 detail。因为伪造 token 有多种失败原因（签名错、格式错、缺字段），锁死文案反而脆弱。

# 三、`tests/test_order.py`（71 行）

## 1-3 行 · 路径常量

```python
'''订单接口测试：创建 / 越权隔离 / 分页 / 参数校验'''

ORDERS = "/api/v1/orders/"
```

🟨 **改参数**，且**结尾斜杠不能省**：路由注册的是 `@router.get("/")`，请求 `/api/v1/orders`（无斜杠）会得到 307 重定向，有的客户端不跟随，表现就是"请求没反应"。

## 逐条详解

### 1. `test_create_order_requires_token`（6-9 行）

```python
resp = await client.post(ORDERS, json={"total_amount": 10})
assert resp.status_code == 401
```

🟨 纯改参数：**写接口必须登录**，这是所有 POST/PATCH/DELETE 的第一道测试。

### 2. `test_create_order_success`（12-20 行）

```python
assert body["order_number"].startswith("ORD-")
assert body["status"] == "待处理"
assert float(body["total_amount"]) == 88.5
assert body["id"] > 0
```

| 行 | 标记 | 说明 |
|---|---|---|
| `startswith("ORD-")` | 🟥 | 断言**格式**而不是具体值。订单号含日期和随机串，不能写死 |
| `status == "待处理"` | 🟥 | **这条最有价值**：证明初始状态由服务端决定。有人把 `Order.create` 里改成别的值，立刻红 |
| `float(...) == 88.5` | 🟥 | **必须 `float()`**：Pydantic 2 把 Decimal 序列化成字符串，POST 返回 `"88.50"`、GET 返回 `"88.5"`，不转就两个接口只能过一半 |
| `id > 0` | 🟥 | 断言"落库成功、主键回填"，不硬编码 id |

### 3. `test_create_order_invalid_amount`（23-26 行）

```python
for bad_amount in (0, -1, 100000000):
    resp = await client.post(ORDERS, json={"total_amount": bad_amount}, headers=auth_headers)
    assert resp.status_code == 422, f"金额 {bad_amount} 应该被拦在接口层"
```

| 元素 | 标记 | 说明 |
|---|---|---|
| `for ... in (0, -1, 100000000)` | 🟥 | **边界值是你自己选的**：0（零值）、-1（负数）、1e8（超出 DECIMAL(10,2) 上界）。一个测试覆盖三个边界，省掉三个几乎一样的函数 |
| `422` | 🟨 | FastAPI 的参数校验失败统一是 422 |
| 断言后的 `f"..."` | 🟩 | 失败时 pytest 会打印这句话，直接告诉你是哪个值漏过了。**写循环测试时一定要加**，否则只看到"某次循环失败" |

### 4. `test_list_returns_own_orders_only`（29-41 行）★ 最重要的一条

```python
async def test_list_returns_own_orders_only(client, auth_headers, login_headers):
    for amount in (10, 20, 30):
        await client.post(ORDERS, json={"total_amount": amount}, headers=auth_headers)

    bob_headers = await login_headers("bob")
    await client.post(ORDERS, json={"total_amount": 999}, headers=bob_headers)

    resp = await client.get(ORDERS, headers=auth_headers)
    assert body["total"] == 3
    assert [float(o["total_amount"]) for o in body["orders"]] == [30.0, 20.0, 10.0]
```

| 元素 | 标记 | 说明 |
|---|---|---|
| 三个参数 | 🟦 | `client` 发请求、`auth_headers` 是 alice、`login_headers` 是工厂用来造 bob |
| `await login_headers("bob")` | 🟨 | **工厂要 await 调用**，和 `auth_headers` 直接用的写法不同 |
| `total == 3` | 🟥 | 4 个订单里只有 3 个属于 alice。**如果 bob 的混进来，这里会变 4** —— 上一轮实验就是这样抓到的 |
| 金额列表断言 | 🟥 | 一次断言两件事：**顺序**（倒序，最新在前）+ **内容** |

**为什么这条最有价值**：删掉 `OrderORM.filter(user_id=...)` 之后，API 依然返回 200、字段全对、金额正确——Swagger 里点一百次都看不出问题。只有换账号才能发现。这就是"认证"和"授权"的分界，也是渗透测试的必查项。

### 5. `test_list_pagination`（44-55 行）

```python
resp = await client.get(ORDERS, params={"limit": 2, "offset": 1}, headers=auth_headers)

assert body["total"] == 3                     # total 是总数，不随分页变小
assert body["limit"] == 2
assert body["offset"] == 1
assert [float(o["total_amount"]) for o in body["orders"]] == [20.0, 10.0]
```

| 元素 | 标记 | 说明 |
|---|---|---|
| `params={"limit": 2, "offset": 1}` | 🟨 | 会被拼成 `?limit=2&offset=1` |
| `total == 3` | 🟥 | **最容易写错的一条**：很多实现会把 `total` 写成"本页条数"，那样这里会是 2。断言 3 才锁住"total 是总数" |
| 回显 `limit`/`offset` | 🟥 | 断言响应里如实回显分页参数，前端靠它对账 |
| `[20.0, 10.0]` | 🟥 | 倒序 30/20/10，跳过第 1 条 → 剩 20、10 |

### 6. `test_list_invalid_pagination`（58-61 行）

```python
resp = await client.get(ORDERS, params={"limit": 0}, headers=auth_headers)
assert resp.status_code == 422
```

🟨 改参数：`limit=0` 违反 `Query(ge=1)`。同类的还能测 `limit=101`（超上界）、`offset=-1`（负数）。

### 7. `test_new_user_sees_empty_list`（64-71 行）

```python
headers = await login_headers("carol")
resp = await client.get(ORDERS, headers=headers)
assert resp.json()["total"] == 0
assert resp.json()["orders"] == []
```

🟥 **`orders == []` 而不是 `None`**：这是这条测试存在的唯一理由。空列表返回 `[]` 前端能直接 `.map()`；返回 `null` 前端就炸。这类"空数据形状"的 bug 只在没数据时出现，平时点不出来。

# 四、新增一条测试的填空模板

想加"取消订单"的测试，不用想结构，填三处空：

```python
async def test_<动作>_<条件>(client, auth_headers):        # 🟨 名字要能念通
    # 1. 准备（可选）：造数据
    order = (await client.post(ORDERS, json={"total_amount": 50}, headers=auth_headers)).json()

    # 2. 执行：发那一个请求
    resp = await client.post(f"/api/v1/orders/{order['id']}/cancel", headers=auth_headers)   # 🟨 换这里

    # 3. 断言：状态码 + 业务事实
    assert resp.status_code == 200                          # 🟨 换这里
    assert resp.json()["status"] == "已取消"                 # 🟥 断言什么由你定
```

三段式（准备 / 执行 / 断言，业界叫 Arrange-Act-Assert）是**唯一需要记住的测试结构**。

# 六、五个常见误改（会毁掉测试价值）

| 误改 | 后果 | 正确做法 |
|---|---|---|
| 代码变了，就去改 `assert` 让它变绿 | **测试变成"记录当前行为"，包括 bug** | 先判断是代码错还是预期错。规则没变就改代码，规则变了才改测试 |
| 为了某个测试，去改 `conftest.py` 的 `TEST_DB_CONFIG` | 一个测试的需求污染全部 15 条 | 用夹具的重载 / 参数化，别改全局配置 |
| 在测试里写 `await asyncio.sleep(1)` | 15 条测试变成 15 秒，且不稳定 | 用 await 代替 sleep；真需要等待就轮询判断 |
| 让测试之间共享数据（"上一个测试建的用户我直接用"） | 单跑能过、全跑就挂，顺序一变全崩 | 每条测试自己造数据。`init_db` 每次重建库，本来就不允许共享 |
| 断言写得太软（`assert resp.status_code in (200, 400)`） | 永远不红，等于没写 | 一个测试只断言一个明确结果 |

最后一条是最隐蔽的：**测试的价值不在于它通过，而在于它**能**失败**。验证方法就是上一轮做的——把代码故意改坏，看它是否变红。

# 七、附录：人名与术语表

## 7.1 测试里的人名（全是编的，项目里没有任何预置账号）

| 名字 | 出现位置 | 代表什么 |
|---|---|---|
| `alice` | `conftest.py:58`，`auth_headers` 夹具 | **默认登录用户**，即"当前用户"。8 条需要登录的测试都用她 |
| `bob` | `test_order.py:33`，`login_headers("bob")` | **第二个用户**，即"另一个人"。唯一用途是证明 alice 看不到他的订单 |
| `carol` | `test_order.py:65`，`login_headers("carol")` | **全新用户**，即"没有任何数据的人"。用来验证空列表返回 `[]` 而不是 `null` |
| `tom` | `test_auth.py` 第 9、13、19、29、31、41 行 | **通用测试用户**，无特殊含义。注册/登录测试只关心"某个人"，随便起的名 |
| `pass1234` | 所有测试 | 统一密码。全部账号都用它，省得记 |

命名来自密码学与协议文档的老传统（`RFC` 里描述双方交互时就用 Alice/Bob）：

| 惯例名 | 常代表 |
|---|---|
| Alice | 发起方 / 甲方 / 当前用户 |
| Bob | 响应方 / 乙方 / 另一个用户 |
| Carol | 第三方 |
| Dave | 第四个参与方 |
| Eve | 窃听者（eavesdropper），测试"别人能不能偷看数据"时用 |
| Mallory | 恶意攻击者（malicious），测试攻击场景时用 |

**四点必须澄清**：

1. **这些账号不存在于你的数据库里**。它们是测试运行时通过 `POST /auth/register` 现场创建的，跑在 SQLite 内存库中，测试结束就消失。刚查过你的 MySQL：`users` 表只有 1 行（`id=1, 用户名=恩杰1`），`orders` 表 2 行，**没有任何 alice/bob/tom**。
2. **每个测试各建一次**。`init_db` 每个测试都重建内存库，所以 `test_login_success` 里的 alice 和 `test_me_with_token` 里的 alice 是两个互不相干的人（虽然同名）。
3. **名字可以随便改**，只要同一测试内前后一致。但建议保留惯例名——它们是全世界工程师的共同语言，别人读你的测试不需要额外解释。
4. **不要用真实用户名**（比如 `恩杰1`）。测试数据里出现真实数据，会让人误以为测试连的是真库。

## 7.2 英文术语中文对照

| 术语 | 中文 | 在本项目里的意思 |
|---|---|---|
| fixture（夹具） | 夹具 / 预置件 | 测试前自动准备好的东西：数据库、客户端、登录态 |
| assert（断言） | 断言 | "我预期这里是这个值"，不成立就抛 `AssertionError` |
| payload（载荷） | 请求体 | 请求里带的数据，测试里写成 `json={...}` |
| headers（请求头） | 请求头 | 放认证信息的地方，`{"Authorization": "Bearer ..."}` |
| status_code（状态码） | 状态码 | 200 成功 / 201 已创建 / 400 业务拒绝 / 401 未登录 / 404 找不到 / 409 冲突 / 422 参数格式错 / 500 服务器炸了 |
| base_url | 基础地址 | 请求路径的前缀，测试里是 `http://test`（假的，不出网） |
| transport（传输层） | 传输层 | httpx 里决定"请求怎么送出去"的组件，`ASGITransport` 表示直接送进应用 |
| ASGI | 异步网关接口 | FastAPI 遵循的 Python 服务端标准，`ASGITransport` 靠它绕开网络 |
| collect（收集） | 收集 | pytest 找出"哪些函数要跑"的动作，只看 `test_` 前缀 |
| Arrange-Act-Assert | 准备-执行-断言 | 一条测试的三段式结构 |
| mock / stub（桩） | 模拟对象 | 用假的替代真依赖（本项目暂时没用） |
| regression（回归） | 回归 | "改 A 把 B 弄坏了"这类问题，测试专治它 |
| migration（迁移） | 数据库迁移 | aerich 生成的版本脚本 |

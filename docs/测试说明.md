# TaskFlow 测试文件说明

本文覆盖测试体系的四个文件：

| 文件 | 角色 | 行数 |
|---|---|---|
| `pytest.ini` | 全局配置，告诉 pytest 怎么跑 | 5 |
| `tests/conftest.py` | 公共夹具，提供数据库和 HTTP 客户端 | 67 |
| `tests/test_auth.py` | 认证接口的用例 | 73 |
| `tests/test_order.py` | 订单接口的用例 | 71 |

当前结果：**15 passed**（8 条认证 + 7 条订单）。

---

## 0. 四者如何协作

```
你在终端敲：python -m pytest
    │
    ├─ pytest 读 pytest.ini
    │     ├─ asyncio_mode=auto        → async def 测试自动当协程跑
    │     ├─ asyncio_default_fixture_loop_scope=function → 每个测试一个事件循环
    │     ├─ testpaths=tests          → 只扫 tests/ 目录
    │     └─ pythonpath=.             → 项目根目录进 sys.path，from main import app 才能成
    │
    ├─ 收集 tests/ 下 test_*.py 里所有 test_* 函数（共 15 个）
    │
    └─ 逐个执行，执行前先按"参数名"自动注入 fixture
          │
          ├─ init_db       （autouse，每个测试都跑）→ 建一个全新的内存库
          ├─ client        （测试函数写了这个参数才有）→ 请求直送 ASGI 应用
          └─ auth_headers  （写了才有）→ 顺手注册+登录，返回可用的认证头
```

关键点：**测试函数只声明参数名，pytest 负责把值塞进来**。`async def test_me_with_token(client, auth_headers)` 里那两个参数没有任何调用方，全是 pytest 按名字从 `conftest.py` 里查出来注入的。

## 1. `pytest.ini`

```ini
[pytest]
asyncio_mode = auto
asyncio_default_fixture_loop_scope = function
testpaths = tests
pythonpath = .
```

### 参数详解

| 参数 | 取值 | 作用 | 不写会怎样 |
|---|---|---|---|
| `asyncio_mode` | `auto` / `strict`（默认） | `auto` 让所有 `async def` 测试函数自动被当作协程测试执行 | 每个测试函数头上都得写 `@pytest.mark.asyncio`，漏一个就**静默跳过**——函数被收集但没真正执行，也不报错，最容易骗人 |
| `asyncio_default_fixture_loop_scope` | `function` / `class` / `module` / `session` | 异步 fixture 默认用哪个级别的事件循环。`function` = 每个测试函数一个全新循环 | 从 pytest-asyncio 0.24 起会刷 `PytestDeprecationWarning`；更重要的是，循环级别和测试级别不匹配时，会出现"事件循环已关闭"或跨测试复用连接导致的状态泄漏 |
| `testpaths` | 目录名 | 只在这些目录里找测试 | 裸敲 `pytest` 会扫描整个项目。你的 `migrations/` 里有 aerich 生成的历史脚本，某些项目还会有 `venv/`、`node_modules/`，全都会被扫一遍，慢且可能误收 |
| `pythonpath` | `.`（项目根） | 把该路径插进 `sys.path`（pytest 7+ 内置，等价于以前在 conftest 里手写 `sys.path.insert`） | `conftest.py` 里 `from main import app` 直接报 `ModuleNotFoundError: No module named 'main'` |

> `function` 这个取值还有个隐含好处：每个测试用独立事件循环 + 独立内存库，配合 `init_db` 的 teardown，**测试之间零共享状态**。所以 `test_list_pagination` 里下的 3 单不会跑到 `test_new_user_sees_empty_list` 里。

## 2. `tests/conftest.py`

`conftest.py` 是 pytest 的约定文件名：它里面的 fixture **自动对同目录及子目录下所有测试生效**，不需要 import。

### 2.1 `TEST_DB_CONFIG`——测试库配置

```python
TEST_DB_CONFIG = {
    "connections": {"default": "sqlite://:memory:"},
    "apps": {
        "models": {
            "models": ["app.infrastructure.database.orm_models"],
            "default_connection": "default",
        }
    },
}
```

结构和 `config/tortoise_config.py` 里的 `TORTOISE_ORM` 完全一致，只把连接串换了。三层含义：

| 键 | 含义 | 说明 |
|---|---|---|
| `connections` | 连接别名 → 连接串的映射 | `default` 是别名，代码里没指定别名时都用它。`sqlite://:memory:` = 纯内存库，进程结束即消失，**不会碰你的 MySQL** |
| `apps` | 逻辑"应用"分组 | Tortoise 支持多 app（比如把报表库单独分组），这里只需要一个 |
| `apps.models.models` | 模型模块的**字符串路径**列表 | 注意是字符串不是模块对象——Tortoise 靠它延迟 import，避免循环依赖。**新增模型文件时这里要加**，但你现在所有 ORM 都在 `orm_models.py` 一个文件里，所以不用动 |
| `default_connection` | 该 app 默认用哪个连接 | 指向 `connections` 里的别名 `default` |

### 2.2 `init_db`——数据库初始化夹具

```python
@pytest_asyncio.fixture(autouse=True)
async def init_db():
    await Tortoise.init(config=TEST_DB_CONFIG)
    await Tortoise.generate_schemas()
    yield
    await Tortoise.close_connections()
```

| 元素 | 含义 |
|---|---|
| `@pytest_asyncio.fixture` | 异步 fixture 必须用这个装饰器（用普通 `@pytest.fixture` 会把协程对象当成返回值，测试里一 await 就炸） |
| `autouse=True` | 自动应用到每个测试，不需要在测试函数参数里声明 |
| `await Tortoise.init(...)` | 建立连接。Tortoise 是全局单例，每个测试重新 init 会覆盖上一次的配置 |
| `await Tortoise.generate_schemas()` | 按模型定义**建表**。测试里不走 aerich——迁移脚本是给生产库升版本用的，测试库每次都是空的，直接按模型建表最省事。顺带也验证了模型定义本身是合法的 |
| `yield` | 分界线：yield 之前是 setup，之后是 teardown。`yield` 不带值 = 这个 fixture 不给测试函数提供任何数据，只是"前后各做一件事" |
| `await Tortoise.close_connections()` | 销毁连接。不写会残留连接池，多个测试累积后可能报连接数超限 |

**为什么不用 `main.py` 的 lifespan 自动初始化**：`httpx.ASGITransport` **不执行 lifespan**（只有 Starlette 的 `TestClient` 会）。指望应用启动时自己连库，测试里 Tortoise 就是未初始化状态，第一个请求直接 `ConfigurationError`。

### 2.3 `client`——HTTP 客户端夹具

```python
@pytest_asyncio.fixture
async def client():
    transport = httpx.ASGITransport(app=app)
    async with httpx.AsyncClient(transport=transport, base_url="http://test") as c:
        yield c
```

| 参数 | 说明 |
|---|---|
| `ASGITransport(app=app)` | 把 FastAPI 应用包成 httpx 的"传输层"。请求不经过 TCP，直接调用 ASGI 接口——**不需要先启动 uvicorn**，也不会占用 8000 端口 |
| `base_url="http://test"` | 必填。httpx 要求请求 URL 是绝对的，测试里只写 `/api/v1/orders/`，前缀由它补。主机名 `test` 是随意起的，反正不会真的发 DNS 查询 |
| `async with ... as c` | 上下文管理器负责关闭客户端连接池；`yield c` 把客户端交给测试函数 |

### 2.4 `_login_headers`——普通辅助函数（不是 fixture）

```python
async def _login_headers(client, username: str, password: str = "pass1234") -> dict:
```

| 参数 | 类型 | 说明 |
|---|---|---|
| `client` | `httpx.AsyncClient` | 显式传入，因为这个函数不是 fixture，拿不到自动注入 |
| `username` | `str` | 必填。用户名必须是唯一的，同一测试里要建多个用户时靠它区分 |
| `password` | `str`，默认 `"pass1234"` | 有默认值，绝大多数用例不用传 |

返回 `{"Authorization": "Bearer <token>"}`，可以直接塞进 `headers=`。

两个细节：

1. **名字以下划线开头**，pytest 不会把它当测试函数收集（顺便，pytest 只收集 `test_` 开头的函数，所以哪怕叫 `login_headers` 也不会被误收）。
2. 它内部先 `register` 再 `login`，且**忽略 register 的返回码**——这样同一个用户名重复调用时，第二次 register 会返回 400（重复），但 login 依然成功。所以在同一个测试里连续调 `login_headers("alice")` 两次也是安全的。

### 2.5 `auth_headers` 与 `login_headers`——两种形态的夹具

```python
@pytest_asyncio.fixture
async def auth_headers(client):
    return await _login_headers(client, "alice")


@pytest_asyncio.fixture
async def login_headers(client):
    async def _make(username: str, password: str = "pass1234") -> dict:
        return await _login_headers(client, username, password)
    return _make
```

| 夹具 | 形态 | 用法 | 适用场景 |
|---|---|---|---|
| `auth_headers` | 直接给值 | `headers=auth_headers` | 只需要一个用户 |
| `login_headers` | **工厂**（返回函数） | `headers = await login_headers("bob")` | 一个测试里要多个用户 |

`login_headers` 是"夹具套函数"的经典写法：fixture 本身返回一个协程函数，测试里再调它。参数 `username` / `password` 和内层 `_make` 完全一致，多这一层只是为了拿到 `client` 的注入。

**为什么不把 token 直接塞进 `client.headers`**：塞进去之后，整个测试里所有请求都带同一个身份，就写不出 `test_list_returns_own_orders_only` 这种"同时扮演 alice 和 bob"的越权测试了。**这是这套夹具最重要的设计决定。**

## 3. `tests/test_auth.py`

开头三个常量只是路径别名，避免每个用例重复写字符串（写错时的报错也更清楚）：

```python
REGISTER = "/api/v1/auth/register"
LOGIN    = "/api/v1/auth/login"
ME       = "/api/v1/auth/me"
```

### 3.1 用例清单

| # | 函数 | 参数 | 请求 | 关键断言 | 验证什么 |
|---|---|---|---|---|---|
| 1 | `test_register_success` | `client` | `POST /register` `{"username":"tom","password":"pass1234"}` | `201`；`username=="tom"`；`user_id>0`；响应里**没有** `password` | 注册主流程 + 不泄露密码 |
| 2 | `test_register_duplicate_username` | `client` | 同一 payload 连发两次 | 第二次 `400`；`detail=="用户名已经存在"` | 唯一性约束被翻译成业务错误 |
| 3 | `test_login_success` | `client` | 注册后 `POST /login` | `200`；`token_type=="bearer"`；`expires_in>0`；`access_token` 用 `.` 切成 3 段 | 登录发 token，且 token 是标准 JWT |
| 4 | `test_login_wrong_password` | `client` | 密码改成 `wrong` | `400`；`detail=="用户名或密码错误"` | 错误密码被拒 |
| 5 | `test_login_user_not_exists` | `client` | 用户名不存在 | `400`；`detail` 同上 | **不暴露"用户不存在"**，防用户名枚举 |
| 6 | `test_me_without_token` | `client` | `GET /me` 无头 | `401`；`detail=="未提供访问凭证"` | 受保护接口的准入 |
| 7 | `test_me_with_token` | `client`, `auth_headers` | `GET /me` 带 token | `200`；`message=="已认证"` | 正常认证通过 |
| 8 | `test_me_with_invalid_token` | `client` | `Authorization: Bearer abc.def.ghi` | `401` | 伪造 token 被验签拦下 |

### 3.2 参数详解

**`client`**：`httpx.AsyncClient` 实例，来自 `conftest.py`。三个方法参数：

```python
await client.post(REGISTER, json={"username": "tom", "password": "pass1234"})
await client.get(ME, headers=auth_headers)
```

| 参数 | 作用 | 说明 |
|---|---|---|
| 第一个位置参数 | URL | 相对路径即可，前缀由 `base_url="http://test"` 补 |
| `json=` | 请求体（JSON） | 自动 `json.dumps` 并设 `Content-Type: application/json`。**FastAPI 的 Pydantic 模型参数只能从这里进** |
| `headers=` | 请求头 | 认证头走这里 |
| `params=` | 查询串（`?k=v`） | `test_order.py` 里的分页用它 |

`json=` 和 `data=` 别混：`data=` 是表单（`application/x-www-form-urlencoded`），FastAPI 的 Pydantic body 收不到，会返回 422。

**`auth_headers`**：dict，形如 `{"Authorization": "Bearer eyJ..."}`。注意这里带 `Bearer ` 前缀，是 `_login_headers` 拼好的——`security.py` 用的是 `HTTPBearer`，它会自己剥掉这个前缀。

### 3.3 两个断言的用意

**`assert "password" not in body`**（第 15 行）

判定的是响应的**顶层键名**里没有 `password`。这是最便宜也最有效的一条回归测试：哪天有人图省事直接在路由里 `return user.__dict__`，密码哈希立刻会漏出去，这条测试当场变红。

**`assert len(body["access_token"].split(".")) == 3`**（第 37 行）

JWT 就是 `header.payload.signature` 三段，用 `.` 分割后长度必须是 3。它比 `startswith("eyJ")` 更强的点在于：如果有人把 token 实现换成了不透明字符串（比如随机 UUID 存 Redis），这条会立刻失败——因为那样 token 就不是 JWT 了，客户端解析逻辑会跟着坏。

## 4. `tests/test_order.py`

```python
ORDERS = "/api/v1/orders/"
```

**结尾的斜杠不能省**。路由注册的是 `@router.get("/")`，请求 `/api/v1/orders`（无斜杠）会得到 307 重定向，而有些客户端不跟随重定向，表现就是"请求没反应"。

### 4.1 用例清单

| # | 函数 | 参数 | 请求 | 关键断言 | 验证什么 |
|---|---|---|---|---|---|
| 1 | `test_create_order_requires_token` | `client` | `POST` 无 token | `401` | 写接口必须登录 |
| 2 | `test_create_order_success` | `client`, `auth_headers` | `{"total_amount": 88.5}` | `201`；`order_number` 以 `ORD-` 开头；`status=="待处理"`；`float(total_amount)==88.5`；`id>0` | 下单主流程 + 订单号/状态由服务端决定 |
| 3 | `test_create_order_invalid_amount` | `client`, `auth_headers` | 依次传 `0` / `-1` / `100000000` | 三次都是 `422` | `Field(gt=0, le=99999999.99)` 生效 |
| 4 | `test_list_returns_own_orders_only` | `client`, `auth_headers`, `login_headers` | alice 下 3 单、bob 下 1 单，用 alice 查 | `total==3`；金额顺序 `[30,20,10]` | **越权隔离** + 默认倒序 |
| 5 | `test_list_pagination` | `client`, `auth_headers` | 下 3 单后 `?limit=2&offset=1` | `total==3`；`limit==2`；`offset==1`；金额 `[20,10]` | 分页切片 + `total` 是总数不是本页数 |
| 6 | `test_list_invalid_pagination` | `client`, `auth_headers` | `?limit=0` | `422` | `Query(ge=1, le=100)` 生效 |
| 7 | `test_new_user_sees_empty_list` | `client`, `login_headers` | 新用户 carol 直接查 | `total==0`；`orders==[]` | 空列表返回结构正确，不是 `null` |

### 4.2 参数详解

**`auth_headers`（直接值）** vs **`login_headers`（工厂）**：

```python
# 第 29-36 行：一个测试里两个身份
async def test_list_returns_own_orders_only(client, auth_headers, login_headers):
    for amount in (10, 20, 30):
        await client.post(ORDERS, json={"total_amount": amount}, headers=auth_headers)

    bob_headers = await login_headers("bob")                          # ← 工厂要 await 调用
    await client.post(ORDERS, json={"total_amount": 999}, headers=bob_headers)

    resp = await client.get(ORDERS, headers=auth_headers)
```

这三行是整个测试套件里最有价值的一段：**同一个 `client`，靠换 `headers` 切换身份**。如果 bob 的单混进了 alice 的结果，`total` 会变成 4，测试立刻红。这就是「认证」和「授权」两层是否真的分工的机器验证。

**`params=`**（第 48 行）：

```python
await client.get(ORDERS, params={"limit": 2, "offset": 1}, headers=auth_headers)
```

| 参数 | 对应路由 | 约束 |
|---|---|---|
| `limit=2` | `Query(10, ge=1, le=100)` | 默认 10，1~100 |
| `offset=1` | `Query(0, ge=0)` | 默认 0，不能为负 |

会被拼成 `?limit=2&offset=1`。`offset=1` 意味着跳过第 1 条，取第 2、3 条，所以断言 `[20.0, 10.0]`（倒序后是 30/20/10，跳过 30）。

**`for bad_amount in (0, -1, 100000000)`**：一个测试里覆盖三个边界值，省掉三个几乎一样的函数。断言里带 `f"金额 {bad_amount} 应该被拦在接口层"`——失败时 pytest 会把这句话打出来，直接告诉你是哪个值漏过了。

### 4.3 两个容易踩的坑

**① 金额断言必须用 `float()`**

同一个订单，两个接口返回的字符串不完全一样：

```
POST /api/v1/orders/ → "total_amount": "88.50"     ← 来自实体 Decimal（quantize 过）
GET  /api/v1/orders/ → "total_amount": "88.5"      ← 来自 ORM 字段再转换
```

原因是 Pydantic 2 把 `Decimal` 序列化成**字符串**。直接写 `assert body["total_amount"] == "88.50"`，POST 能过、GET 会挂。统一用 `float()` 比较，语义也更准——比的是金额数值，不是字符串格式。

（两位小数的金额用 float 比较是安全的；这不影响"后端计算金额不能用 float"那条规矩，测试里只是读值比较。）

**② 列表顺序断言依赖 `Meta.ordering`**

`test_list_returns_own_orders_only` 断言 `[30.0, 20.0, 10.0]`，前提是 `OrderORM.Meta.ordering = ["-created_at"]`。三个订单是循环里快速连续创建的，`created_at` 可能落到同一秒——如果哪天换成只到秒精度的字段，顺序就不稳定了。真遇到偶发失败，加一个显式排序断言或让 ORM 加 `-id` 作为次级排序键。

## 5. 运行与排查

```bash
cd D:\pythonpro\TaskFlow
python -m pytest            # 全跑
python -m pytest -v         # 每个用例一行
python -m pytest -q         # 精简输出
python -m pytest tests/test_order.py            # 只跑一个文件
python -m pytest -k "pagination"                # 按名字过滤
python -m pytest -x         # 第一个失败就停
python -m pytest --lf       # 只跑上次失败的（last-failed）
python -m pytest -s         # 不捕获 print 输出，调试用
```

预期：

```
15 passed, 3 warnings in ~4.4s
```

3 条 warning 来自 tortoise 内部的 `pk` / `index` 参数弃用提示，与项目代码无关，可以忽略。

### 常见报错对照

| 报错 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError: No module named 'main'` | `pytest.ini` 缺 `pythonpath = .`，或没在项目根目录执行 | 补配置 / `cd` 到 `D:\pythonpro\TaskFlow` |
| `fixture 'client' not found` | `conftest.py` 不在 `tests/` 下，或文件名拼错 | 放回 `tests/conftest.py` |
| `async def functions are not natively supported` | 缺 `asyncio_mode = auto`，或没装 `pytest-asyncio` | 补配置 / `pip install pytest-asyncio` |
| `ConfigurationError: Tortoise initialization ...` | `init_db` 没执行（比如它被改成了非 autouse 且没声明） | 检查 `autouse=True` |
| 测试把 MySQL 里的数据改了 | `TEST_DB_CONFIG` 的连接串被误改成 MySQL 地址 | 必须是 `sqlite://:memory:` |
| 偶发 `database is locked` | 多个测试共用一个内存库（循环作用域被改成 session） | 保持 `asyncio_default_fixture_loop_scope = function` |

### 还缺的用例（按优先级）

1. **订单状态变更**：合法流转（待处理→已支付）、非法流转（已支付→已取消）、他人订单（应 404 而非 403）
2. **注册参数边界**：空用户名、超长用户名、空密码——目前会被 `register_user.py` 里的 `ValidationError` 拦成 400，但没测试锁住
3. **token 过期**：把 `access_token_expire_minutes` 临时调成 0 或负数，验证返回 401「凭证已过期」
4. **并发**：两个协程同时取消同一单，验证条件更新只成功一次
